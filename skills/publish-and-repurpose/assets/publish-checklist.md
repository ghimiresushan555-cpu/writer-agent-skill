# Publish checklist — <slug>

Copy into the `## Checklist` section of `published/<slug>.md`. Every row gets `done`, or `skipped — <reason>`. No blank rows.

## Truth

- [ ] Zero unresolved claims; `## Verification` from the edited draft is clean
- [ ] Every number has source, date, unit, baseline
- [ ] Every quote is verbatim and attributed with role and date
- [ ] Every link resolves at publish time (re-check; sites rot)
- [ ] Superlatives have a defined universe
- [ ] Disclosures present (advising, sponsorship, employment, conflict)
- [ ] Permission obtained for any reproduced document, screenshot, or private message

## Text

- [ ] Title chosen from five options, scored on clarity / specificity / honesty / length
- [ ] Dek written (15–30 words), not a summary of the first paragraph
- [ ] Meta description 140–160 characters, contains the search phrase naturally
- [ ] Slug matches the pipeline slug; canonical URL set
- [ ] One H1; H2s say something; skim test passes
- [ ] Byline, date, read time
- [ ] Spelling variant consistent; numbers and dashes per house style

## Access

- [ ] Alt text on every image, describing function not filename
- [ ] Contrast and font size checked in the rendered email and on mobile
- [ ] Long paragraphs broken for phone width
- [ ] Any chart has a text description of the takeaway
- [ ] No meaning carried by colour alone

## Email

- [ ] Subject line ≤ 45 characters where possible, no emoji unless in voice
- [ ] Preview text written separately (not the first line of the body)
- [ ] Rendered and checked on a phone at 375px
- [ ] One primary CTA, above the fold
- [ ] Unsubscribe and sender identity correct
- [ ] Send window matches the audience's actual reading habits

## Distribution

- [ ] LinkedIn cut: first two lines work before "see more"
- [ ] X cut: post one carries the whole argument
- [ ] Each surface reformatted, not truncated
- [ ] Link placement per surface convention
- [ ] Scheduled with staggered times, not all at once

## After

- [ ] Backlog row updated to `status: published`
- [ ] Follow-up idea captured (a published piece usually creates one)
- [ ] Analytics or open-rate comparison date noted for a week out
- [ ] Corrections process known and linked, in case one is needed
