# Channel formats

Constraints and native moves per surface. Treat the character and word counts as hard limits; treat the "native move" column as the actual work.

## Newsletter

| Constraint | Value |
| --- | --- |
| Subject line | ≤ 45 characters where possible; 60 absolute |
| Preview text | 40–90 characters, written separately |
| Body | `cadence.target_words` ±20% |
| Links | ≤ 12 (more reads as a digest) |
| Read time | 4–6 minutes for a weekly essay |

**Native move:** the issue should work as a standalone letter to one person. The first line is the hook, not a greeting. Greetings ("Hi all," "Hope you're well") cost the best line in the piece.

## Blog (canonical)

| Constraint | Value |
| --- | --- |
| Title | ≤ 60 characters |
| Meta description | 140–160 characters |
| H1 | one, containing the primary phrase |
| Subheads | H2s that are claims or questions |
| Internal links | 2–3, descriptive anchors |
| Canonical | set, pointing here if syndicated elsewhere |

**Native move:** a blog post can be longer and can carry the full mechanism. If the newsletter is the excerpt, the blog is the reference version — add the table, the document, the full method.

## LinkedIn

| Constraint | Value |
| --- | --- |
| Length | 150–300 words; 1,300 characters max |
| First two lines | must land before the "see more" fold |
| Links | in the body reduces reach; in comments is the common workaround |
| Hashtags | 0–3, only if the channel's audience uses them |
| Paragraphs | 1–2 sentences, with blank lines between |

**Native move:** open with the claim, not the context. White space is the formatting. No "I'm excited to share" and no "Agree?" close. One number, one lesson, one question that invites a real answer.

## X / Twitter

| Constraint | Value |
| --- | --- |
| Single post | ≤ 280 characters |
| Thread | 5–7 posts, each a complete thought |
| Links | final post, or first post if the link is the point |
| Hooks | number, tension, or refusal — not "a thread 🧵" |

**Native move:** post one must contain the entire argument compressed. If a reader stops after post one, they should still have received something true and useful. Post two is the mechanism; the last post is the link or the action.

## YouTube / video description

| Constraint | Value |
| --- | --- |
| Title | ≤ 70 characters, front-loaded |
| Description | first 2 lines visible; 150 characters |
| Chapters | 4–8, timestamped |
| Thumbnail text | ≤ 5 words |

**Native move:** write for the person deciding whether to click, then for the person who already watched. Chapters are a table of contents, not a transcript.

## Podcast show notes

| Constraint | Value |
| --- | --- |
| Summary | 80–120 words |
| Timestamps | 5–8, named by claim not topic |
| Links | every person and thing mentioned |
| Transcript | if published, lightly cleaned, never reworded |

**Native move:** the show notes are an index of the *claims*, so a listener can quote the episode without re-listening.

## Quote / image card

| Constraint | Value |
| --- | --- |
| Text | ≤ 20 words, verbatim from the piece |
| Attribution | name + channel handle |
| Alt text | full sentence describing the card's meaning |

**Native move:** pick the sentence a reader would screenshot. If nothing in the piece is screenshot-worthy, that's a signal about the piece, not the card.

## Cross-posting rules

1. **Reformat, don't truncate.** A cut-and-pasted paragraph that ends mid-sentence is the tell.
2. **No "new post!" scaffolding.** Lead with the content; the link is the afterthought.
3. **Stagger by hours, not minutes.** Different audiences, different waking hours.
4. **One idea per surface.** If you have three, spread them across three posts over a week.
5. **Adapt the hook, keep the fact.** The number and the quote must stay identical everywhere, or readers who follow you on two platforms will notice the drift.
